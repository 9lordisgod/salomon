## 0. One-line rule
The agent **proposes** unsigned drafts (intent JSON, hashes, human summaries). It never holds, sees, requests, or uses signing material, and nothing it produces is settled, MPC-signed, or broadcast inside the loop.

## 1. Custody boundary (PS gate 4 — named before any sign path)
| Zone | Holds | May do | Never |
|---|---|---|---|
| **Model (GLM in TEE, verified-remote)** | prompt + sanitized msgs + UNTRUSTED tool envelopes | call read-only + propose tools | see keys/seeds/signatures; call sign/settle/broadcast |
| **Agent host (phase2 loop, our process)** | public account IDs, env config (contract IDs), drafts | build/validate drafts, hash them, wrap outputs UNTRUSTED | load keys, call `execute_intents`, MPC `sign`, `broadcast_tx_*` |
| **Signer (OUTSIDE loop)** — user wallet / user device / intent relayer / future TEE signer | private keys | review human summary + draft hash, sign NEP-413/etc., submit | — |
Hand-off artefact leaving the host = `{draft_json, draft_sha256, human_summary}`. Signer must recompute `draft_sha256` from `draft_json` itself (hash-then-sign preference, PS soft). The signed payload never re-enters model context.

## 2. Threat model
1. **Key in model context** — user pastes seed/`ed25519:` secret, or a tool/quote result contains key-like material. ⇒ sanitizer rule `key_material_in_context` runs on every message (user + role:tool) **before attest/complete**; hit ⇒ `AgentDenied("key_material_in_context")` (PS gate 3). Logs digest-only; offending text never logged.
2. **Prompt injection via tool/quote data** — chain state, solver quotes, relayer responses are UNTRUSTED (same `wrapUntrusted` envelope; PS soft: solvers/relayers untrusted for content).
3. **Intent forgery / tampering** — model or injected data steers receiver, amount, token, deadline, verifying contract. Mitigations: strict schema; `verifying_contract` + allowed token IDs come **only from env config** (never model-filled, never hardcoded/invented — env TBD); human summary generated deterministically by host from the draft, not by the model; signer verifies hash.
4. **Replay / cross-chain confusion** — nonce generated by host (not model), deadline capped; derived-address path reuse across chains forbidden (path must embed chain id; collision ⇒ deny).
5. **Capability creep** — any tool name matching `/sign|submit|broadcast|settle|execute_intents|send_tx/i` refused at registration and at execute (fail-closed).

## 3. Data flow
user ask → `sanitizeMessages` (+ `key_material_in_context`) → attest (allowlist/CM/compose pin) → verified GLM complete → tool call:
- read-only (existing `NearReadOnlyTools`, optional quote shapes) → result `wrapUntrusted`
- `propose_intent` / `preview_derived_address` / `prepare_foreign_tx` / `propose_chain_sig_request` → **local only, no RPC sign** → validated draft + `draft_sha256` + host-built summary → `wrapUntrusted` back to model
→ final answer + draft artefact returned to caller → **human/wallet signs OUTSIDE loop** (not M4).

## 4. Tools — IN (M4, Lead-binding)
| Tool | Does | Output |
|---|---|---|
| `propose_intent` | Build **unsigned** Verifier-shaped payload draft (`transfer`, `token_diff`, `ft_withdraw` subset) | draft + sha256 + summary, UNTRUSTED |
| quote shapes (optional, read-only) | e.g. 1Click `/v0/quote` *dry* or message-bus quote read; types only in M4, no auth token invented | UNTRUSTED |
| `preview_derived_address` | Compute/preview chain-signature derived address for `(predecessor, path, chain)`; public data only | address + path, UNTRUSTED |
| `prepare_foreign_tx` | Unsigned foreign-chain tx skeleton + human summary | draft + sha256 + summary |
| `propose_chain_sig_request` | Unsigned MPC sign *request* draft (payload hash + path) + summary — **not submitted** | draft + sha256 + summary |
All: `additionalProperties:false`, fail-closed validation, outputs wrapped UNTRUSTED, `execute()` of any resulting action ⇒ `NotImplemented`/`AgentDenied`.

## 5. Tools — OUT (forbidden in M4)
Verifier settle (`execute_intents`, also `simulate_intents` with signed payloads) · MPC `sign` call · any broadcast (`broadcast_tx_*`, relayer publish, 1Click submit/deposit) · agent-held signing keys (no key load, no NEP-413/ERC-191 sign inside loop) · inventing `intents.near` / MPC / token contract IDs (env-configured, TBD) · derivation path reuse across chains.

## 6. Intent draft schema (sketch)
Based on official Verifier payload (`signer_id, verifying_contract, deadline, nonce, intents[]`).
```ts
type IntentKind = "transfer" | "token_diff" | "ft_withdraw";
interface IntentDraft {
  schema: "m4.intent_draft.v0";
  signer_id: string;            // MODEL proposes, host validates ACCOUNT_RE; signer confirms
  verifying_contract: string;   // HOST from env (INTENTS_VERIFIER_ID); model value ignored/denied
  deadline: string;             // HOST: now + min(model_ttl, MAX_TTL=10min), ISO-8601
  nonce: string;                // HOST: base64 32B, placeholder salt (real salt fetched read-only, TBD)
  intents: Array<{ intent: IntentKind; receiver_id?: string; tokens?: Record<string,string>; diff?: Record<string,string> }>; // MODEL; tokens ∈ env allowlist, amounts decimal-string u128
  unsigned: true;               // literal; no signature/public_key fields allowed
}
interface DraftArtefact { draft_json: string; draft_sha256: string; human_summary: string /* host-generated */; }
```
Validation rejects: any `signature`/`public_key`/`private_key`/`seed` field; unknown intent kinds; non-allowlisted tokens; negative/zero/oversized amounts (spend cap §11.1); >4 intents.

## 7. Plug-in to existing code
- `agentLoop.ts`: tool list = `TOOL_SPECS` + `PROPOSE_TOOL_SPECS` behind flag `enablePropose` (default off). System prompt gains: "you may only propose unsigned drafts; you cannot sign, settle, or broadcast."
- New `src/tools/nearIntentsPropose.ts` (`ProposeTools implements ToolExecutor`); composite executor routes read-only vs propose; unknown ⇒ `wrapUntrusted(name,false,{error:"unknown_tool"})`.
- `FORBIDDEN_TOOL_RE` (narrowed, G1 fix — the old `/sign|submit|…/i` substring form matched `propose_chain_signature`; tool renamed to `propose_chain_sig_request` AND regex narrowed to whole underscore segments):
  `FORBIDDEN_TOOL_RE = /(^|_)(sign|submit|broadcast|settle|execute|simulate|send|publish|deposit|withdraw_now)(_|$)/i`
  plus exact set `FORBIDDEN_TOOL_NAMES = {sign, submit, broadcast, settle, execute_intents, simulate_intents, send_tx, mpc_sign, broadcast_tx_commit, broadcast_tx_async, sign_message, sign_intent}`.
  Forbidden ⇔ name ∈ set OR regex matches. Does NOT match `propose_intent`, `propose_chain_sig_request` (segment `sig` ≠ `sign`), `prepare_foreign_tx`, `preview_derived_address`, `quote_intent`, or any read-only tool (tested). Applied at registration (throw), executor (wrapped deny) and loop (AgentDenied).
- `sanitize.ts`: add `key_material_in_context` rule (ed25519:/secp256k1: secret-length base58, 12/24-word BIP39 heuristic, PEM, `private_key`/`seed_phrase` keys) — **applies to role:tool too**; maps to `AgentDenied` (existing SanitizerRejected→AgentDenied path).

## 9. Test plan / first-evidence criteria
Unit (mocked, no network, no keys):
1. **propose ≠ sign:** propose output has `unsigned:true`, no signature/public_key fields; `executeIntent/signDraft/broadcast` throw `NotImplemented`; loop reaching them ⇒ `AgentDenied`.
2. Registering/invoking any tool matching FORBIDDEN_TOOL_RE ⇒ throw/deny.
3. `key_material_in_context` in user msg and in role:tool ⇒ `AgentDenied` **before** attest/complete (assert attest+complete mocks never called).
4. Model-supplied `verifying_contract` ignored/denied; env missing ⇒ `env_unconfigured`.
5. Schema rejects: unknown kind, non-allowlisted token, bad amount, >4 intents, extra fields, past/too-far deadline.
6. `draft_sha256` == sha256(draft_json); summary deterministic.
7. Derived-address: same path across two chains ⇒ deny `path_reuse_across_chains`.
8. Outputs wrapped UNTRUSTED; injection string inside quote stays inert data.
9. Existing 38/38 phase2 + 112/112 phase1.5 still green.
Optional dry-run evidence: verified-remote GLM asked "send 10 wNEAR to bob.near" ⇒ emits `propose_intent` call ⇒ artefact; digest-only log; zero keys in env of process; no RPC write method observed (fetch mock asserts only `query`/`block`/`gas_price`/`tx`).

## 11. Locked decisions (Lead + PS G1, binding)
1. **Spend caps:** env `MAX_DRAFT_AMOUNT` (NEAR, decimal) REQUIRED — missing ⇒ deny `draft_amount_cap_missing`. Network ceilings (Lead pick, PS agreed): **testnet = 1000 NEAR**, **mainnet = 10 NEAR** (strict until G3); env value above ceiling ⇒ deny. Draft amounts are yocto/raw u128 decimal strings, normalised by token decimals (`TOKEN_ALLOWLIST` = `token_id@decimals`). Checked **per-intent** (each token amount) and **per-draft** (sum) ⇒ `draft_amount_cap_exceeded`.
2. **`simulate_intents` FORBIDDEN until G3** (needs signed payload).
3. **`key_material_in_context`:** secret-length only — ed25519 secret (≥80 base58), PEM private keys, labelled `private_key/secret_key/seed_phrase/mnemonic`, labelled secp256k1 secrets, xprv, BIP39 runs. Public `ed25519:` keys (view_access_key_list) are OK. Applies to every role incl. wrapped role:tool; never relaxed; ⇒ AgentDenied before attest/complete.
4. **HARD:** Completions receive only `{draft_sha256, human_summary, unsigned:true, schema}` (UNTRUSTED-wrapped). Full `draft_json` stays host-side (`ProposeTools.getArtefact`) → outer caller only.
5. **Contract IDs:** env only (`INTENTS_VERIFIER_ID`, `MPC_CONTRACT_ID`, `TOKEN_ALLOWLIST`, `NETWORK`); Lead owns `.env.example` (testnet-first, values TBD/empty); AE does not invent; no hardcoded mainnet IDs; PS reviews values at G2.
